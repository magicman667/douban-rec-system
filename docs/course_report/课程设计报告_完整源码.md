## 摘要

针对传统电影推荐系统过度依赖单一绝对均分与协同过滤、普遍忽视跨题材评分基线差异以及两极分化影片“踩雷”风险的问题，本文设计并实现了一套面向评分分歧感知的大数据电影推荐与排雷系统——知影（CinePulse / TDC-Rec）。系统基于华为云 8 vCPU / 32 GiB ECS 构建逻辑三节点完全分布式集群（1 Master + 2 Worker，共 7 个 Docker 容器），协同整合 Hadoop 3.3.6（HDFS + YARN）、Apache Hive 3.1.3、Apache Spark 3.5（SQL / MLlib / Structured Streaming）、MongoDB 7.0 文档库与 Weaviate v1.40.6 双命名向量数据库，对豆瓣公开数据集 MovieData-10M 全量数据（140,502 部电影、4,169,028 条有效评分、600,344 位用户、1,048,575 条中文短评）开展离线数仓清洗、按用户时间轴 8:2 防穿越切分与多模持久化。算法层面，系统由“单阶段手工重排”升级为工业级三阶段非深度学习架构：第一阶段融合 Spark ALS 50 维协同向量与 BGE-small-zh 512 维中文语义向量，引入按历史评分数自适应的加权倒数秩融合策略（tdc-fusion-v3），在 50,000 名独立测试用户上将 NDCG@10 提升 37.8%、Recall@10 提升 23.9% 且稳妥用户零踩雷；第二阶段采用严格两阶段时序防穿越切分（Stage-1 249.0 万 / Stage-2 78.0 万 / 封存测试集 89.8 万），构建 21 维稠密与 18 维稀疏特征，在 6 组非深度学习精排模型（纯 ALS、L2-LR、Spark YARN 分布式 GBT、FM 分解机、GBDT+LR、Hist-GBDT）上实测对比，最优 Hist-GBDT 测试 ROC-AUC 达 0.8296（较纯 ALS 跃升 +7.06 个百分点），用户内 GAUC 达 0.7857，线上 50 候选精排 P95 延迟仅 9.93 ms；第三阶段提出香农熵—双峰耦合分歧指数与 0–100 直观标尺，施加非对称 1.5 次幂超额风险惩罚与单题材多样性约束，在 185,149 名全库评测用户上将长尾覆盖率由 5.68% 提升 5.8 倍至 33.23%，并将 28,077 名稳妥防雷派用户的踩雷率压降至 0.0000%，同时通过 Spark Structured Streaming 实现 9.88 秒级 1★ 差评激增实时熔断预警，并借助 Streamlit + DuckDB + Plotly 交付公网可交互 Web 系统与 16 张大数据洞察图表。

**关键词**：大数据架构；Hadoop/Spark；多模数据库；Weaviate 向量检索；评分分歧度；非深度学习精排；防踩雷推荐；TDC-Rec

## Abstract

Conventional movie recommendation systems rely heavily on absolute average ratings and single-stage collaborative filtering, overlooking inherent genre rating biases and the risk of recommending highly polarizing films to risk-averse viewers. This report presents CinePulse (TDC-Rec), a divergence-aware, anti-landmine movie recommendation and analytics platform built upon a full-stack big data infrastructure. Deployed on a Huawei Cloud ECS (8 vCPU / 32 GiB RAM) as a 3-node logical cluster via Docker Compose (1 Master + 2 Workers, 7 containers), the platform orchestrates Hadoop 3.3.6 (HDFS/YARN), Apache Hive 3.1.3, Apache Spark 3.5 (SQL, MLlib, and Structured Streaming), MongoDB 7.0, and Weaviate v1.40.6 dual-vector search over the complete Douban MovieData-10M corpus (140,502 movies, 4,169,028 valid ratings, 600,344 users, and 1,048,575 Chinese reviews). Algorithmically, we construct a three-stage non-deep-learning funnel: (1) Stage-1 dual-vector recall combining 50D Spark ALS and 512D BGE-small-zh embeddings with history-adaptive weighted RRF (tdc-fusion-v3), improving NDCG@10 by +37.8% and Recall@10 by +23.9% across 50,000 independent users; (2) Stage-2 classical ML fine-ranking under a strict two-stage chronological anti-leakage split (2.49M Stage-1 / 0.78M Stage-2 / 0.899M sealed test), comparing six models over 21 dense and 18 sparse features where Hist-GBDT achieves 0.8296 ROC-AUC (+7.06pp over pure ALS) and 0.7857 GAUC with 9.93 ms P95 inference latency (and distributed Spark YARN GBT achieves 0.8249); (3) Stage-3 asymmetric divergence-aware reranking with a Shannon-entropy & bimodal controversy index mapped to a 0–100 gauge, lifting long-tail Coverage@10 from 5.68% to 33.23% while eliminating conservative-user landmine exposure to 0.0000%, paired with 9.88s Structured Streaming surge alerts and an interactive Streamlit + DuckDB + Plotly web application.

**Keywords**: Big Data Architecture; Apache Spark; Polyglot Persistence; Weaviate HNSW; Rating Divergence; Classical ML Ranking; TDC-Rec

## 第 1 章 绪论与项目破题定位

### 1.1 研究背景与现实痛点

随着流媒体平台与影评社区的爆发式增长，影视内容规模已突破数十万量级。以豆瓣电影为代表的中文影视社区汇聚了数千万观众的真实星级评分与短评文本，但海量数据也带来了显著的“选片决策焦虑”。传统课程项目或早期工业推荐系统多采用单一的 UserCF、ItemCF 或基础矩阵分解（ALS/SVD），按预测平均分由高到低截取 Top-10 推送给用户。在真实中文观影场景中，这种“唯均分论”存在三方面根本缺陷：

- 缺陷一：忽视评分分布形态（“均分迷信”）。两部平均分相近的热门影片，其口碑结构可能截然相反——例如《霸王别姬》在 116.7 万人评价中几乎全员给出 4–5 星（本系统分歧指数仅 20/100），而《大鱼海棠》（33.8 万人评）或《无极》（14.6 万人评）则是 5 星力荐与 1 星怒骂激烈撕裂的两极争议片（分歧指数 79–81/100）。向追求稳妥观影的观众推荐高争议大片极易引发严重负反馈（即“踩雷”）。
- 缺陷二：忽视跨题材天然均分偏移（“类型偏见”）。在全量 140,502 部豆瓣电影的实测统计中，动画片平均贝叶斯口碑高达 3.53、剧情片达 3.48，而恐怖片仅 2.89、惊悚片 3.09、科幻片 3.14。若跨题材直接按绝对均分排序，小众高口碑恐怖/科幻佳作将被系统性埋没，榜单高度向头部剧情片集中。
- 缺陷三：推荐黑盒与实时响应缺失。传统离线批处理推荐系统既无法向用户解释“为何推荐该片、分歧点在哪”，也无法在影片遭遇突发口碑崩盘（近期 1 星差评激增）时及时熔断预警，更缺乏在用户发现高风险争议片后一键提供“同类型零差评平替”的闭环能力。

### 1.2 三大核心破题视角与创新目标

围绕上述痛点与《大数据架构与技术》课程对分布式存储、批流计算、多模数据库及量化评估的综合考核要求，本项目提出“打破类型偏见、打破均分迷信、打破推荐黑盒”三大破题视角，构建端到端可复现、公网可交互的知影（CinePulse / TDC-Rec）推荐与排雷系统：

- 全满贯大数据多模底座：单台华为云 ECS 上通过 Docker Compose 编排逻辑三节点 Hadoop 3.3.6（HDFS + YARN）与 Spark 3.5 集群，集成 Hive 3.1.3 离线数仓、MongoDB 7.0 文档库、Weaviate v1.40.6 双命名向量引擎及 Spark Structured Streaming 实时流计算，全面覆盖课程核心组件。
- 原创 TDC-Rec 类型去偏与分歧感知建模：基于 80% 历史训练集并行计算同类型贝叶斯平滑相对分 Z(i|g) 与“香农熵—双峰”耦合分歧指数 C_i，并将其归一化至 0–100 直观三色标尺（0–35 口碑一致 / 36–69 温和分化 / 70–100 两极争议），同时刻画 600,344 位用户的个体争议容忍度 τ_u。
- 工业级三阶段非深度学习推荐漏斗：摒弃课程中易被认为过于简单的单一余弦/规则公式，升级为“Stage 1 自适应加权双向量召回（tdc-fusion-v3）→ Stage 2 21 维交叉特征非深度学习机器学习精排（Spark YARN GBT / Hist-GBDT / GBDT+LR / FM / L2-LR）→ Stage 3 非对称防雷重排与实时熔断”完整三阶段架构。
- 透明可解释交互与实机公网交付：基于 Streamlit + DuckDB + Plotly 构建暗黑影院级三视图 Web 系统（发现电影 / 口碑全景 / 观影发现），支持 4 套精排引擎一键切换、AI 口碑排雷与 3 部零差评平替推荐，以及 16 张可溯源至真实 CSV 的大数据分析图表。

### 3.2 标准化清洗流水线、异常隔离与确定性 ID 映射

原始 CSV 数据存在大小写表头不统一（movies/ratings 为全大写，comments 为全小写）、多编码混杂（UTF-8 与 GB18030）、剧情简介与短评内嵌换行符破坏行结构、电影类型与制片地区采用“/”斜杠拼接、以及用户标识为 32 位哈希字符串 USER_MD5（无法直接输入 Spark MLlib ALS 整型接口）等典型工业级脏数据问题。我们在 01_cluster_hive/clean.py 中依托临时 SQLite 唯一索引与确定性流水线实现了可复现清洗：

- 多编码与文本净化：对 movies.csv 和 ratings.csv 使用 UTF-8-SIG 严格解析，对 comments.csv 采用 GB18030 容错读取；对所有字符串字段执行 " ".join(val.split()) 清除内嵌换行符与多余空白；将斜杠拼接的 genres 与 regions 拆分为规范数组，并提取首个类型作为 main_genre。
- 异常隔离留痕：校验 movie_id 非空、评分值位于 [1, 5] 闭区间且时间戳可合法解析为 ISO 时间格式，并依据 (user_md5, movie_id, rating_time, rating) 唯一键去重。全量执行中精准拦截并隔离 392 条无效评分至审计文件，保留 4,169,028 条纯净评分。
- USER_MD5 确定性整数化映射：将全部 600,344 个唯一 USER_MD5 按字典序确定性映射为连续 32 位正整数 user_id（1 ~ 600,344），并将映射表持久化为 user_mapping.csv，保证多模块之间用户主键 100% 一致。

### 3.3 防数据穿越的按用户时间轴 8:2 切分策略

推荐系统离线实验最常见的隐蔽错误是采用全局随机切分（Random Split），这会导致模型用用户“2019 年的打分”去预测“2015 年的观影行为”，造成严重的未来信息穿越（Data Leakage）。本项目在清洗阶段即执行严格的按用户时间轴切分：

- 对每位用户的全部历史评分，按 (rating_time ASC, rating_id ASC) 确定性排序（同一秒内的多条评分由 rating_id 保证顺序唯一可复现）；
- 对仅含 1 条历史记录的冷启动用户，保底留入训练集以保留其档案；对含 k >= 2 条记录的用户，按时间顺序取前 80%（向上取整）划入训练集 train_ratings，最后 20% 划入封存测试集 test_ratings；
- 全量切分结果经 verify_split.py 交叉核验：train_ratings 精确为 3,270,299 条（78.44%），test_ratings 精确为 898,729 条（21.56%），严格满足每位用户 max(train_time) <= min(test_time)，且任何特征工程、贝叶斯均值、分歧度计算与 ALS 训练严禁触碰 test_ratings。

## 第 4 章 分布式特征工程、耦合分歧建模与 Spark ALS 训练

### 4.1 第一阶画像一：同类型贝叶斯平滑去偏相对分 Z(i|g)

仅基于 Hive 80% 训练集 douban_db.train_ratings，我们在 02_spark_als/feature_engineering.py 中利用 Spark SQL 并行扫描聚合每部影片的评分数 n_i、原始均分 r̄_i、标准差 σ_i 与五档星级直方图 hist_5bins。为同时克服“极小样本 5 星虚高”与“跨题材天然均分偏见”，首先计算各主类型 g 的全局均值 μ_g 与标准差 σ_g，再以先验平滑权重 m = 20 将影片原始均分向所属主类型均值做贝叶斯收缩，并计算其在类型内部的标准化相对分 Z(i|g)：

> **公式**：`R_Bayes(i) = ( n_i · r̄_i + 20 · μ_g ) / ( n_i + 20 )      ；      Z(i | g) = ( R_Bayes(i) − μ_g ) / σ_g`

数值算例校验：假设恐怖片主类型均值 μ_g = 3.05, σ_g = 0.65，动画片主类型均值 μ_g = 4.05, σ_g = 0.45。现有两部均获 n_i = 80 人评价的影片：一部原始均分 3.80 的恐怖片经贝叶斯平滑得 R_Bayes = 3.65, Z = +0.92（属于恐怖片中的顶尖佳作）；一部原始均分 3.85 的动画片得 R_Bayes = 3.89, Z = −0.36（在动画片中反而低于均线）。通过引入 Z(i|g)，系统成功打破了绝对均分带来的类型偏见。

### 4.2 第一阶画像二：“香农熵—双峰”耦合分歧指数与 0–100 标尺

单纯使用评分方差或标准差无法区分“所有人集中打 3 星（平庸均匀）”与“一半人打 5 星、一半人打 1 星（极端两极撕裂）”。为此，本项目原创提出“香农熵—双峰”耦合分歧指数 C_i ∈ [0, 1]，将归一化标准差 σ̃_i = σ_i / 2.0、好差评双峰极化度 B_i = 4 · P(r ≥ 4) · P(r ≤ 2) 以及五档归一化香农信息熵 H̃_i = −(1 / ln 5) · Σ p_{i,b} ln p_{i,b} 进行加权耦合，并乘以样本置信因子 n_i / (n_i + 20) 压制极小样本噪声：

> **公式**：`C_i = [ n_i / ( n_i + 20 ) ] × ( 0.40 · σ̃_i + 0.35 · B_i + 0.25 · H̃_i )  ∈ [0, 1]`

典型波形算例对比（设 n_i = 100）：① 温和共识佳作 [0, 5, 15, 65, 15] 的 C_i ≈ 0.293；② 五档均匀平庸片 [20, 20, 20, 20, 20] 的 C_i ≈ 0.631；③ 两极对骂争议片 [40, 5, 0, 15, 40] 的 C_i ≈ 0.747。为提升前端普通用户的直觉可读性，系统进一步通过分段线性映射将原始 C_i 投射至 0–100 统一分歧标尺（与推荐阈值精确对齐）：

| 原始 C_i 区间 | 0–100 分歧标尺 | 口碑分级与视觉色标 | 物理含义 | 全量实测高可信代表影片 |

## 第 5 章 工业级三阶段 TDC-Rec 推荐算法、非深度学习精排与流式预警

### 5.1 架构演进：从单阶段规则重排到工业级三阶段漏斗

常规课程设计往往止步于单一余弦相似度、KNN 或纯手工线性加权公式，在特征表达能力与排序精度上存在明显天花板；而盲目堆砌重型深度学习网络（如 DeepFM/DIN）在无 GPU 环境下不仅训练成本高、解释性差，且在中小规模表格特征上往往不如梯度提升树与分解机。因此，本项目在保留原创 TDC-Rec 分歧防雷思想的基础上，迭代升级为标准工业级“多路召回 → 非深度学习机器学习精排 → 分歧防雷重排与实时熔断”三阶段推荐漏斗，如图 5-1 所示。

*图 5-1 三阶段 TDC-Rec 工业级推荐漏斗与严格两阶段时序防穿越切分示意图*（高清实图已内嵌于 Word `.docx` 与 `.pdf` 版本）

### 5.2 Stage 1：Weaviate 双向量检索与自适应加权 RRF 召回（tdc-fusion-v3）

为兼顾“用户历史协同品味”与“中文语义内容覆盖（解决 72,050 部冷门无评片冷启动）”，系统使用中文预训练句向量模型 BAAI/bge-small-zh-v1.5 将全部 140,502 部电影的片名、类型、地区、标签与剧情简介编码为 512 维语义向量，并与 50 维 Spark ALS 协同隐向量一同以双命名向量（Named Vectors）形式灌入宿主机 Weaviate v1.40.6，建立 Filtered HNSW 近似最近邻索引。

在融合 ALS 与 BGE 两路候选排序时，原始版本采用固定权重 50%:50% 与常数 k=60 的倒数秩融合（RRF）。针对不同活跃度用户在协同信号丰度上的显著差异，我们进一步在 03_weaviate_stream_eval/fusion_policy.py 中引入了经 20,000 名调参用户网格搜索、50,000 名独立用户验证的自适应加权 RRF 策略（tdc-fusion-v3）：

> **公式**：`S_RRF(u, i) = (k + 1) × [ w_ALS / (k + rank_ALS(i)) + (1 − w_ALS) / (k + rank_Vec(i)) ]`

| --- | --- | --- | --- | --- | --- |
| 0 条 | 纯冷启动新用户 | 50% | 50% | 60 | 缺乏协同信号，均衡依赖内容语义兜底 |
| 1 – 9 条 | 低频稀疏用户 | 70% | 30% | 100 | 提高协同占比并用更大 k 压制排名噪声，召回增益最显著 |

此外，在线推荐服务（04_web_app/service_access.py）针对首页页面级核查发现的“冷门音乐现场 DVD（仅 300–500 人评）霸榜”和“猎奇探索派召回池中缺乏 ≥70 分两极片”两大工程痛点，增设了 Channel B 画像对齐高可信补充召回与分级门控机制：在“主流口碑（≥100 样本、≥2 万人评）”和“经典热片（≥100 样本、≥5 万人评）”模式下，补充高样本、多题材均衡且严格符合画像分歧区间的代表性候选进入精排池（同时保留“全库挖宝”无门槛长尾模式），彻底根治了冷门噪音与模式错配问题。

### 5.3 Stage 2：严格两阶段时序防穿越与 21 维非深度学习机器学习精排

将第一阶段 ALS 内积作为第二阶段树模型特征时，最大的学术与工程陷阱是 Stacking 训练集内记忆泄露：若用同一批训练数据既训 ALS 又训 GBDT，实测 ALS 在自身训练集内的 ROC-AUC 虚高达 0.9748，导致树模型完全“偷懒背题”、线上泛化暴跌。为此，02_spark_als/prepare_ml_dataset.py 将原 327.0 万训练评分按时间轴再次严切为 Stage-1（前 2,490,122 条，专训 Stage-1 ALS 向量与统计特征）与 Stage-2（后 780,177 条，专训 5 大 ML 精排模型），完全封存 898,729 条测试集仅作终极评测。切分后 ALS 内积在 Stage-2 上的 AUC 为 0.7662，与封存测试集 0.7601 高度吻合，证实零泄露。

在此无穿越样本上，系统抽取了涵盖协同匹配、影片口碑分歧、用户严苛画像与高阶交互四大维度的 21 维稠密特征（表 5-2）及 18 维稀疏 One-Hot 特征（主类型与用户画像类别），统一定义正样本为“用户打分 r ≥ 4 星”，构建二分类排序精排任务。

| 特征族 | 特征名称（代码字段） | 维数 | 物理与业务含义 |
| --- | --- | --- | --- |
| 协同向量匹配 | als_dot, als_cos, user_als_norm, movie_als_norm | 4 | 50 维 ALS 协同内积、余弦相似度、用户活跃模长与电影流行模长 |

在 02_spark_als/spark_ml_pipeline.py 与 train_ml_rankers.py 中，我们系统性实现并横向对比了 5 类极具代表性的经典非深度学习精排算法（完全不含深度学习网络）：

- L2-LR（L2 正则逻辑回归）：基于标准化 21 维稠密特征学习线性加权概率，作为全特征线性基准验证多源特征增量；
- Spark MLlib YARN GBT（分布式梯度提升树）：将特征矩阵 staging 至 HDFS，真实提交 2-Worker Hadoop YARN 集群（application_1795351088747_0004，耗时 43.49 s）训练分布式 GBTClassifier，体现大数据分布式机器学习落地能力；
- FM 因子分解机（Factorization Machine, Rendle 2010）：自主使用纯 NumPy + AdaGrad 优化器实现隐因子维度 k=16 的二阶分解机，对全部 21 稠密 + 18 稀疏特征（共 39 维）显式建模任意两两特征的隐向量二阶交叉 w_0 + Σw_i x_i + Σ<v_i, v_j>x_i x_j；
- GBDT+LR 树叶交叉精排（He et al., ADKDD 2014 经典范式）：先训练梯度提升决策树提取每条样本落入的叶子节点编号，经稀疏 One-Hot 编码后拼接原稠密特征输入 L2 稀疏逻辑回归，实现三至四阶非线性特征自动组合与精准概率校准；
- Hist-GBDT（直方图梯度提升树，240 棵树）：基于连续特征分箱加速的高精度集成树模型，捕获精细非线性边界，最终打包为仅 0.46 MB 的轻量权重包（ml_ranker_bundle.joblib），由 03_weaviate_stream_eval/ml_ranker.py 加载实现线上 50 候选 P95 延迟 9.93 ms 实时推理。

### 5.4 Stage 3：非对称分歧防雷重排、零差评平替与流式实时预警

拿到第二阶段模型实时输出的真实合拍度概率 P_ML(u, i) 后，第三阶段保持概率本身诚实展示（前端卡片标注“合拍 XX%”），同时在最终排序分上叠加 TDC-Rec 原创非对称分歧控制、热度/样本可信度微调与单题材多样性打散（Top-10 中同主类型 ≤ 4 部）：

> **公式**：`RankScore(u, i) = P_ML(u, i) − 0.65 · 𝕀(τ_u ≤ 0.5) · max(0, C_i − τ_u)^1.5 + 0.26 · 𝕀(τ_u > 0.5) · C_i`

当用户点开任意争议电影的“排雷详情”时，系统同步调用 get_controversy_detail_and_twins(movie_id)：① 从 MongoDB 取出精选五星/一星短评并生成正反方交锋摘要（AI 口碑排雷卡）；② 利用该片 512 维 BGE 语义向量在 Weaviate 中实时检索“同主类型且分歧度 C < 0.50”的 Top-3 稳妥相似片作为零差评平替。与此同时，01_cluster_hive/stream_alert.py 运行 Spark Structured Streaming 滑动窗口微批任务，持续监控模拟实时评分 JSON 流（movie_id, rating, event_time），一旦捕获窗口内 1★ 差评激增立即原子更新 MongoDB stream_alert=True，实测端到端延迟仅 9.881 秒，前端顶部实时弹出《无极》《捉妖记》《魔宫魅影》熔断警报条。

### 7.3 工程挑战反思、系统局限与后续优化方向

在从原型到全量上线的完整工程实践中，团队直面并解决了多项真实生产难题，同时也客观识别了当前系统的边界与改进空间：

- 已攻克的工程难题：① 修正了单台 ECS 多容器共享磁盘下的内存 OOM 风险（容器硬限额 21.5 GiB）；② 发现了 Stacking 两阶段未切分导致的 ALS 训练集内 AUC 虚高陷阱（0.9748 → 0.7601）并通过严格时序隔离根治；③ 排查并解决了 Weaviate 候选集遗漏 rating_count 特征导致冷门 300 人评音乐 DVD 混入首页的问题；④ 统一了卡片角标与 0–100 分歧标尺的渲染口径，消除“绿标红条”冲突。
- 当前局限与后续展望：① 受单台 ECS 资源所限，逻辑三节点并行加速比无法等同于跨物理机集群线性扩展，未来可迁移至多台物理云主机验证大规模水平伸缩；② 公开数据集单片抽样上限约 300–400 条且截止至 2019 年，未来可接入增量爬虫管道与近五年院线新片；③ 当前在线精排按用户静态画像打分，未来可引入用户当次会话点击反馈，结合在线增量学习（Online FTRL / Bandit）实现实时偏好演化。

### 7.4 全文总结

本课程设计围绕中文电影推荐场景中的“均分迷信”“类型偏见”与“黑盒踩雷”三大痛点，完整走通了从 416.9 万条豆瓣真实评分清洗、华为云逻辑三节点 Hadoop/Hive/Spark 分布式集群部署、MongoDB 与 Weaviate 多模数据库协同、三阶段非深度学习 TDC-Rec 推荐算法研发、严格防穿越量化消融实验，到公网 7×24 暗黑影院级 Web 产品交付的全链路工程闭环。系统不仅全面覆盖并超额达成《大数据架构与技术》课程各项核心技术指标（ROC-AUC 0.8296 较纯 ALS 跃升 +7.06pp、自适应 RRF 召回 NDCG@10 提升 +37.8%、长尾覆盖率提升 5.8 倍、28,077 名稳妥用户踩雷率 0.0000%、在线精排 P95 延迟 9.93 ms），更在可解释性、交互体验与工程规范性上达到了可直接线上演示验收的水准。
